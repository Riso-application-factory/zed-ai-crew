# Creating, Updating, and Rebuilding Zed Docs (`docs/`)

Zed's documentation lives in `docs/` and is built with **mdBook** plus a custom Rust preprocessor/postprocessor crate (`crates/docs_preprocessor`).

## 1. Key Files & Directory Layout

- **`docs/book.toml`**: mdBook configuration, preprocessor/postprocessor setup, and URL redirects (`[output.zed-html.redirect]`).
- **`docs/src/SUMMARY.md`**: Table of contents that defines the sidebar structure and controls which `.md` files mdBook compiles. **Any `.md` file in `docs/src/` not listed in `SUMMARY.md` is ignored by mdBook.**
- **`docs/src/`**: Markdown source files for all documentation pages.
- **`docs/book/`**: Compiled HTML output generated by `mdbook build docs`.
- **`crates/docs_preprocessor/`**: Custom preprocessor (expands `{#kb ...}`, `{#action ...}`, etc.) and postprocessor (injects per-page `<title>` and `<meta name="description">` from front matter, and emits redirect HTML files).

---

## 2. Creating a New Documentation Page

### Step 1: Create the `.md` file in `docs/src/`

Start every page with front matter at the very top of the file (no leading blank lines, single-line ASCII values only, **no double quotes** around values):

```markdown
---
title: Page Title - Zed
description: One-sentence summary of what this page covers.
---

# Page Heading

Introductory paragraph explaining what you can accomplish.

## Getting Started {#getting-started}
```

> **Front matter constraints (`docs_preprocessor`):**
> - Keys (`title`, `description`) and values must be on a single line.
> - Do **not** wrap values in double quotes (`title: "My Title"` will break).
> - Use plain ASCII text (no unicode/emoji).

### Step 2: Register the file in `docs/src/SUMMARY.md`

Add a link to the new file under the appropriate `# Section` in `docs/src/SUMMARY.md`:

```markdown
# Privacy & Security

- [Worktree Trust](./worktree-trust.md)
- [Privacy for Business](./business/privacy.md)
- [Telemetry](./telemetry.md)
- [SOC2](./soc2.md)
```

- Use `./relative/path.md` links.
- Indent nested child pages by **2 spaces** per level.
- Use `- [Draft Title]()` (empty parentheses) for unlinked draft chapters.

## 3. Updating Existing Documentation

### Custom Preprocessor Syntax

Never hardcode default keybindings when an action exists. Use the preprocessor macros instead:

| Syntax | Purpose | Example |
| --- | --- | --- |
| `{#kb scope::ActionName}` | Renders platform-aware keybinding | `{#kb zed::OpenSettings}` |
| `{#kb:jetbrains scope::ActionName}` | Resolves keybinding from overlay first | `{#kb:jetbrains editor::GoToDefinition}` |
| `{#action scope::ActionName}` | Renders human-readable command name | `{#action agent::ToggleFocus}` |

### Formatting & Structure Conventions

- **Section anchors**: Add explicit anchors to headings for stable cross-linking:
  ```markdown
  ## Custom Models {#anthropic-custom-models}
  ```
- **Settings & Keymap JSON blocks**: Tag JSON blocks with `[settings]` or `[keymap]` and always show complete, valid JSON structure:
  ````markdown
  ```json [settings]
  {
    "format_on_save": "on"
  }
  ```
  ````
- **Callouts**: Use bold labels inside blockquotes:
  ```markdown
  > **Note:** Important context.
  > **Tip:** Helpful workflow shortcut.
  > **Warn:** Potential pitfall or limitation.
  ```
- **Images/Videos**: Do not commit binary assets into the repo. Host externally (e.g., `https://zed.dev/img/...`) and link to them.
- **Renaming or moving a page**:
  1. Update the link path in `docs/src/SUMMARY.md`.
  2. Update any relative cross-links in other `docs/src/**/*.md` files.
  3. Add a redirect entry under `[output.zed-html.redirect]` in `docs/book.toml` (source path must not start with `/docs` and must end with `.html`; target path starts with `/docs/` and ends with `.html`).

### Voice & Style Rules (from `docs/.rules` & `docs/AGENTS.md`)

- **Second person, present tense**: Address the reader as "you" ("Zed opens the file", not "The user will see").
- **Direct & practical**: Avoid marketing fluff ("powerful", "seamless") and hedging words ("simply", "just", "easily").
- **Settings Editor first**: Explain how to configure an option in the Settings Editor UI first, followed by "Or add this to your `settings.json`:".
- **Terminology**: Use *folder* (not directory), *project* (not workspace), *Settings Editor* (not settings UI), *command palette* (not command bar), and specific panel names (*Project Panel*, *Terminal Panel*).

## 4. Formatting, Rebuilding, and Previewing Docs

### Format with Prettier (Required before committing)

All files in `docs/src/` must adhere to `docs/.prettierrc` (80-character line width):

```sh
cd docs && pnpm dlx prettier@3.5.0 . --write
```

Or check formatting without modifying files:

```sh
cd docs && npx prettier --check src/
```

### Generate Action Metadata (When validating actions/keybindings)

`docs_preprocessor` validates `{#kb ...}` and `{#action ...}` against `crates/docs_preprocessor/actions.json`. Generate or refresh this file from the repo root when needed:

```sh
./script/generate-action-metadata
```

*(Note: If `actions.json` does not exist, `docs_preprocessor` skips action/keybinding validation with a warning rather than failing the build.)*

### Build / Rebuild Docs (`mdbook build`)

**Important:** Always remove `docs/book` before running a fresh build (`rm -rf docs/book`), because `docs_preprocessor postprocess` emits redirect `.html` files into `docs/book/` and errors out (`Error: Unable to emit redirects ... because it already exists`) if a previous build's redirect files are still present.

From the repository root:

```sh
rm -rf docs/book && mdbook build docs
```

Or using Nix (which provides pinned `mdbook` 0.4.40 and a prebuilt `docs_preprocessor`):

```sh
rm -rf docs/book && nix develop -c mdbook build docs
```

Compiled HTML output is written to `docs/book/` (e.g. `docs/book/sop.html`).

### Live Preview (`mdbook serve`)

To run a local live-reloading server at `http://localhost:3000`:

```sh
rm -rf docs/book && mdbook serve docs
```

### Troubleshooting Builds

- **`Error: Unable to emit redirects ... because it already exists`**: Run `rm -rf docs/book` before `mdbook build docs` or `mdbook serve docs`.
- **mdBook version**: Use `mdbook@0.4.40` (or `0.4.37` in CI). Avoid `0.4.48`, which causes broken URL behavior. Install via:
  ```sh
  cargo install mdbook@0.4.40
  ```
- **Bypassing the preprocessor for quick layout checks**: If you want to test raw mdBook rendering without compiling/running `docs_preprocessor`, temporarily comment out `[preprocessor.zed-docs-preprocessor]` in `docs/book.toml` (and revert before committing).
