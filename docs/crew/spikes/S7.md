## Implementation under test

The spike adds `--crew-mcp-bridge <socket>` immediately after argument parsing,
beside the early `--askpass` dispatch in `crates/zed/src/main.rs`. The bridge
uses a Unix stream with independent stdin-to-socket and socket-to-stdout copies.
It copies bytes without adding framing or diagnostic text to stdout. Stdin EOF
shuts down the socket's write side. Failures go to stderr.

Do not call `askpass::main`: it reads stdin to EOF, appends a NUL byte, and waits
for a single response. Only its early argument dispatch is applicable to MCP.

The temporary `--crew-spike-server` mode starts the actual
`context_server::listener::McpServer::new`, registers `crew_ping`, and prints
an out-of-band descriptor containing `server.socket_path()` and
`std::env::current_exe()`. The provider command comes from this absolute app
path. The PATH `zed` CLI is not used.

`McpServer` already writes one JSON message followed by `\n` and reads with
`BufReader::read_line`. It does not use Content-Length headers or askpass's NUL
separator. Its socket is `mcp.sock` inside a retained `zed-mcp*` temporary folder.
The bridge needs no JSON parser.

`McpServer` only has built-in `tools/list` and `tools/call` dispatch. The host must
register `Initialize` with `handle_request::<Initialize>` and advertise
`ServerCapabilities { tools: Some(...), ..Default::default() }`. Notifications
without IDs, including `notifications/initialized`, are ignored by the listener.
T2.1 must also decide which other standard methods (for example `ping`) to expose.

## Reproduction

The spike branch contains:

- `crates/zed/src/crew_mcp_spike.rs`: actual MCP host, deterministic `crew_ping`
  response `crew_pong`, and the streaming bridge.
- `spikes/s7/framing.py`: actual host and app bridge round trip for initialize,
  initialized notification, tools/list, tools/call, unknown-method error,
  fragmented JSON lines, and stdin EOF.
- `spikes/s7/capabilities.mjs`: initialize-only probes, with no model prompt.
- `spikes/s7/results.json`: sanitized measured versions, completion status,
  tool titles, permission options and selected choices; excludes account and
  session identifiers.
- `spikes/s7/provider-runner.mjs`: one short prompt for one provider; accepts an
  absolute `current_exe`/socket descriptor, records permission options, allows
  only the requested `crew_ping` permission, and rejects other tool permissions.
- `spikes/s7/acp-client.mjs`: the existing ACP probe helper, copied without
  credentials. It starts adapters using the login-shell environment without
  printing that environment. New temporary ACP traffic files are private scratch
  data, not report fixtures; do not publish them.

```sh
cargo build -p zed --offline
python3 spikes/s7/framing.py /absolute/path/to/target/debug/zed
/absolute/path/to/target/debug/zed --crew-spike-server > /tmp/crew-s7-server.json
# Keep that server running while executing the following commands elsewhere.
node spikes/s7/provider-runner.mjs claude /tmp/crew-s7-server.json
node spikes/s7/provider-runner.mjs codex /tmp/crew-s7-server.json
node spikes/s7/provider-runner.mjs antigravity /tmp/crew-s7-server.json
```

The provider receives:

```json
{
  "name": "crew",
  "command": "/absolute/path/from/current_exe",
  "args": ["--crew-mcp-bridge", "/absolute/path/to/zed-mcpXYZ/mcp.sock"],
  "env": []
}
```

## Consequences for T2.1

The bridge/transport spike is accepted; there is no provider transport blocker.
Keep the host's initialize handler and advertised tools capability, launch the
absolute app path from `current_exe`, retain `McpServer` for the session lifetime,
and preserve stdout as protocol bytes. Permission requests differ by provider;
this probe establishes the observed options above, not a universal absence of
Codex permission prompts.

An absent `stdio` boolean in `mcpCapabilities` does not mean lack of stdio:
stdio is the base ACP MCP server shape. The live initialize responses advertised
Claude `{http: true, sse: true}`, Codex `{acp: false, http: true, sse: false}`,
and Antigravity `{http: true, sse: true}` while all three accepted the stdio
configuration used here.

The spike tests transport and a harmless empty-input tool only. It does not
establish production authorization policy, cancellation, crashes, hostile socket
clients, large-message behavior, or every standard MCP method. Those remain
implementation and test responsibilities for T2.1 and its dependent tasks.
No environment dump, credentials, account identifiers, provider history, or raw
ACP traffic is included in this report.
