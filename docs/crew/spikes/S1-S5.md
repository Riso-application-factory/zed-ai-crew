## Provenance and method

This report packages Human's Q1–Q5, Q1b and Q3b results supplied in [spec appendix B.3](../tech-spec.md#phu-luc-b) and the [spike inventory](../spike-list.md#phan-1). The supplied experiments ran on 2026-10-25, macOS, fork `20ea81ef29`, `claude-agent-acp@0.95.0`, `codex-acp@2.2.2`, `antigravity-acp` 1.4.3, ACP crate 3.4.0 (schema 1.12.0). The original method used ACP session options and role markers, compaction/load/resume probes, login failure cases, sandbox file/network operations and adapter slash-command output. Findings below retain **[Spike]** or **[Đã kiểm]** labels from the supplied sources; they are not new measurements.

## S1 / Q1 and Q1b: ROLE channels and persistence

| Provider / layer | Supplied finding | Consequence |
| --- | --- | --- |
| ACP 3.4.0 | **[Spike]** `system_prompt` exists on new/load/fork/resume; content is an array of content blocks. | Keep the fork ACP version for M0; no forced migration to v2. |
| Claude | **[Spike]** ACP `systemPrompt` with `mode: append` works over three turns and `/compact`; it takes priority over `_meta.systemPrompt`. Load/resume rebuilds options from the request; omission loses the appended ROLE. The fallback is an object `{ "append": "<ROLE>" }`; a string replaces the base prompt. | CrewConnection resends complete SessionOptions on every load/resume path. |
| Antigravity / Q1b | **[Spike]** Ignores ACP `systemPrompt`; accepts a string at `_meta.antigravity.systemPrompt.append` on new/load/resume. Other types are silently ignored. ROLE is not stored with the conversation; the ROLE-only marker survives compaction in `<user_system_instructions>` and survives model changes. | Validate the string type and resend ROLE/options from the first load/resume request. |
| Codex | **[Đã kiểm]** `newSession` reads string `_meta.jetbrains.air.customInstructions` into `threadStart.developerInstructions`; load/resume code does not read it. | Runtime ROLE proof remains T1.6; persistence across restart remains S11/T2.10. |

Affected requirements: [NEED 55](../brief.md#need-55), spec 6.1/6.2/14, T1.4/T1.6/T1.7/T2.10. These findings do not close S11.

## S3 / Q3 and Q3b: Claude sandbox and sensitive paths

| Probe | Supplied finding **[Spike]** | Required layers |
| --- | --- | --- |
| Out-of-worktree writes | Bash with sandbox enabled rejects writes outside the worktree/home with EPERM; sandboxed Bash auto-allows without a permission request. | `enabled: true`, `failIfUnavailable: true`, `allowUnsandboxedCommands: false`; measure gate coverage in S8/S9. |
| Network | A new host requests SandboxNetworkAccess; allowed hosts remain allowed for the session. Strict allowlist plus allowedDomains or a rejection blocks access. | `network.strictAllowlist: true`, effective allowlist, host-aware gate. |
| Sensitive paths / Q3b | Default sandboxed Bash can read sensitive paths. `filesystem.denyRead` or `credentials.files` blocks Bash access, including the Keychain command; the Read tool instead follows permissions requests or `settings.permissions.deny`. | Combine Bash denyRead, `Read(//<path>/**)` deny rules and a gate rejecting out-of-worktree reads/edits. Denylists retain risk R12. |
| Shared temporary folder / Q3b | Claude forces every worker TMPDIR to `/tmp/claude-501`, even if the session overrides TMPDIR. `filesystem.denyWrite` for this folder blocks writes; temporary files then fall into the worktree. | Deny that shared write path, commit only declared artifacts and clean undeclared files at worker end. |
| Persistent permission options | Editing outside cwd offers `allow_always`. | Select only `allow_once` or `reject_once` by kind; never allow/reject-always. |

Affected requirements: [NEED 07](../brief.md#need-07), [NEED 31](../brief.md#need-31), NEED 02/55, spec 6.2/10.4, T3.5/T3.6/T3.7/T3.9. This report records supplied observations only; future experiments must use fake secret files and never read real credential files.

## S4 / Q4: Antigravity Ultra behavior

**[Spike]** The supplied model list is `gemini-4-argon`, `gemini-3.8-flash`, `claude-opus-5-5`, `claude-sonnet-5-5`, `gpt-oss-120b-medium`; thinking levels are low/medium/high. Store model candidates as `(provider, model, effort)` and query live snapshots rather than treating this dated list as permanent.

**[Spike]** The first prompt costs about 12.7k tokens of built-in instructions. Four parallel prompts worked; the adapter imposed no cap in this probe. Reuse probe sessions, include startup cost in scheduling and enforce Crew's own concurrency limits (Human's Q7 remains a decision).

**[Spike]** Compaction occurs around 256k tokens despite a reported context window near 1M. ACP emits no compaction notification; `usage_update.used` falls sharply (approximately 210k to 23k in the supplied example). Use measured compaction budgets and detect a large usage drop (spec 6.8, T3.7).

**[Spike]** Sessions persist in provider storage and appear in session/list/import; ACP offers no delete. Reuse probes, filter Crew/probe sessions at H5e, and do not inspect or delete provider storage outside ACP (NEED 61).
